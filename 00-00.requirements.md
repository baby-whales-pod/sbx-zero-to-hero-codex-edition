## Prerequisites

- Every user has a GitHub handle
- Every user has created a GitHub repository (`hello-sbx`) to follow this hands-on
- Every user has a **Docker account** to authenticate the `sbx` CLI (create one at <https://hub.docker.com/signup> if needed)
- Every user has an **OpenAI API key** (`sk-...`) and OpenAI API credits to authenticate and use the Codex agent

## Setup

Look at: https://docs.docker.com/ai/sandboxes/#get-started

### Install `sbx` (per OS)

> ✋ **Docker Desktop is not required to use `sbx`.**

**macOS** — *macOS Sonoma (14)+, Apple silicon*:

```bash
brew trust docker/tap
brew install docker/tap/sbx
sbx login
```

**Windows** — *Windows 11, 64-bit x86_64, Windows Hypervisor Platform enabled*:

```powershell
# enable the hypervisor platform once (elevated PowerShell)
Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform -All

winget install -h Docker.sbx
sbx login
```

### Linux

**Ubuntu 24.04+ or Linux Mint 22.x** — *x86_64 or aarch64, KVM enabled, and the user in the `kvm` group*:

```bash
# Check KVM is available, then add your user to the kvm group
lsmod | grep kvm
sudo usermod -aG kvm "$USER"
```

Sign out and back in after changing group membership, or run `newgrp kvm`.

**Ubuntu 24.04+:**

```bash
curl -fsSL https://get.docker.com | sudo REPO_ONLY=1 sh
sudo apt-get install -y docker-sbx
```

**Linux Mint 22.x:** the Docker installation script may incorrectly configure the Debian repository. Use Docker’s Ubuntu 24.04 “Noble” repository instead:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl

sudo rm -f /etc/apt/sources.list.d/docker.list \
  /etc/apt/sources.list.d/docker.sources
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu noble stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null

sudo apt-get update
sudo apt-get install -y docker-sbx
```

Verify the installation and sign in:

```bash
sbx version
sbx login
```

`sbx login` opens a browser and asks you to sign in to your Docker account using a one-time device confirmation code. Complete this flow before running your first sandbox. Docker authentication and Codex authentication are separate: the Docker account signs the `sbx` CLI in, while the OpenAI API key below authenticates the Codex agent.

> Linux Mint is not an officially supported Docker Sandboxes host, but this installation path has been verified on Linux Mint 22.3.
>
> 📖 Always-current prerequisites and steps: https://docs.docker.com/ai/sandboxes/#get-started.

### Authenticate the Codex agent

Then store your OpenAI API key as a global `sbx` secret (once):

```bash
sbx secret set -g openai
```

> The key is kept in your OS keychain on the host. The proxy injects it into outbound requests to `api.openai.com`; inside the sandbox `OPENAI_API_KEY` only ever holds a `proxy-managed` placeholder.

### Inject a GitHub token (PAT)

To let the agent **push code and use the `gh` CLI** from inside the sandbox (module 2), the proxy needs a GitHub credential. You give it a **Personal Access Token (PAT)** stored as an `sbx` secret — exactly like the OpenAI key, the token stays on the host and is injected at the network level, so the sandbox never sees it in clear text.

First, create a PAT on GitHub (**Settings → Developer settings → Personal access tokens**):

- **Classic token** with the `repo` scope (add `workflow` if you will touch GitHub Actions), **or**
- a **fine-grained token** scoped to your `hello-sbx` repo with *Contents: read/write* and *Issues: read/write*.

Then store it globally (once, for all sandboxes):

```bash
# interactive — paste the PAT when prompted
sbx secret set -g github
```

Or non-interactively, reading the token from your existing `gh` login or an env var:

```bash
# reuse the token from the gh CLI on your host
sbx secret set -g github -t "$(gh auth token)"

# or pipe it from an environment variable / secret manager
echo "$GITHUB_TOKEN" | sbx secret set -g github
```

> - Same proxy model as the OpenAI key: the PAT lives in your host keychain and is injected only toward `github.com` / `api.github.com`. Inside the sandbox `gh auth status` will say **"not logged in"** — that is expected; the credential is injected by the proxy, not by the `gh` CLI.
> - Scope it to a single sandbox instead of all with `sbx secret set <sandbox-name> github`.
> - On first use you may be asked to **approve the GitHub domains** (the same v2 bindings consent as for OpenAI) — see [`troubleshooting/openai-credential-no-domains-allowed.md`](./troubleshooting/openai-credential-no-domains-allowed.md).
