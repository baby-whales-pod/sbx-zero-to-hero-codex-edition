# Environment variables injection
> `sbx` without ai governance policy

> [!NOTE]
> In this lesson you will inject a persistent environment variable into a running sandbox, then read it back — both from a shell and from the Codex agent.

## Why inject environment variables?

A sandbox boots clean and does **not** inherit your host's shell environment. Injecting variables hands the agent the **non-secret configuration** it needs (an endpoint, a feature flag, a build setting like `GOFLAGS`/`NODE_ENV`…) without baking an image or committing to the repo. Appended to `/etc/sandbox-persistent.sh`, the value **persists across every shell, the agent's tool calls, and sandbox restarts** — set once, available everywhere inside the box.

> ⚠️ These variables are **plain, readable configuration** — the agent sees them in clear text. Do **not** store credentials or API keys this way. For secrets, use `sbx secret` instead (proxy-injected, never visible inside the sandbox) — see [`03-02.secrets-injection.md`](./03-02.secrets-injection.md).

## Inject environment variables into a sandbox

Retrieve the name of your sandbox:
```bash
sbx ls
```
> It should be `codex-hello-sbx`

### Add an environment variable to the sandbox

In a terminal, type the below command:
```bash
# run a single command with variables set
sbx exec -d codex-hello-sbx bash -c "echo 'export HELLO_MESSAGE=\"Hello World\"' >> /etc/sandbox-persistent.sh"
```

Then check the value:
```bash
# open an interactive shell in the sandbox:
sbx exec -it codex-hello-sbx bash
# Then type
echo $HELLO_MESSAGE
```

From the interactive agent:

```text
please, display $HELLO_MESSAGE
```
