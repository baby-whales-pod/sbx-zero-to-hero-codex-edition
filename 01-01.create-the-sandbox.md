# Create the sandbox
> `sbx` without ai governance policy

> [!NOTE]
> In this lesson you will authenticate the Codex agent with your OpenAI API key, create your first isolated sandbox, and sign the `sbx` CLI in to Docker when prompted — then learn how to reconnect after you leave.

### Authenticate Codex (once) with your OpenAI API key

Codex authenticates with an **OpenAI API key**. Store it once as a global `sbx` secret — you do **not** need to log in from inside the sandbox:

```bash
sbx secret set -g openai
```

Paste your `sk-...` key when prompted.

> The key stays in your host keychain. The proxy injects it into outbound requests to `api.openai.com`; the sandbox only ever sees a `proxy-managed` placeholder in `OPENAI_API_KEY`.

```bash
sbx secret ls
```

> 🔀 **OAuth alternative (ChatGPT login).** Instead of an API key you can use a browser-based OAuth flow: `sbx secret set -g openai --oauth`. This edition of the hands-on uses the **API key**.

> 📖 Reference: <https://docs.docker.com/ai/sandboxes/agents/codex/>

### Create your first `sbx` sandbox

- git clone your `hello-sbx` repository: `git clone git@github.com:k33g/hello-sbx.git` (replace `k33g` with your GitHub handle)
- `cd hello-sbx`
- `code .`
- open a terminal in VSCode

Then create your first sandbox:

```bash
#sbx policy allow network api.openai.com,openai.com
sbx run codex
```

The first time you run this command, `sbx` tells you that you are not authenticated to Docker and starts a browser-based device confirmation flow. Sign in with your Docker account, confirm the one-time code shown in the terminal, and return to the terminal. If you do not have a Docker account, create one at <https://hub.docker.com/signup>.

After authentication, `sbx` asks you to initialize the global network policy. Select:

```text
2. Balanced — Default deny, with common dev sites allowed.
```

Press `2`, then `Enter`, or use the arrow keys to select **Balanced** and press `Enter`. This workshop uses the Balanced policy because it permits common development services while denying other network traffic by default. The selection applies to current and future sandboxes and can be changed later with `sbx policy` commands.

Once the agent starts, Codex launches straight into its prompt. It does not ask for a separate Codex login because the OpenAI API key is already injected by the proxy. (The Docker sign-in described above is still required for `sbx` itself.)

You can now type a first instruction, e.g.:

```raw
who are you and what model are you running?
```

### Reconnect to the sandbox (after you exit)

Leaving the agent (`Ctrl-C`, typing `exit`, or just closing the terminal) does **not** delete the sandbox — it keeps living in the background. You can hop back in at any time.

First, find your sandbox (its default name here is `codex-hello-sbx`):

```bash
sbx ls
```

**Re-attach to the Codex agent** — either from anywhere, by name:

```bash
sbx run --name codex-hello-sbx
```

…or simply re-run the same command from inside the `hello-sbx` folder (since the sandbox already exists, `sbx run` re-attaches instead of creating a new one):

```bash
sbx run codex
```

**Just need a shell** in the sandbox (not the agent)? Open one directly:

```bash
sbx exec -it codex-hello-sbx bash
```

> You can also reconnect from the `sbx` dashboard: run `sbx`, pick your sandbox, and choose **exec** — see [`01-02.walk-into-the-sandbox.md`](./01-02.walk-into-the-sandbox.md).

When you are completely done and want to get rid of it:

```bash
sbx rm codex-hello-sbx
```
